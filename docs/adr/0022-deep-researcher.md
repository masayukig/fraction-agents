# 0022. deep research の係（deep-researcher）: ウェブと public のリポジトリを読み、実行せずにレポートにする

- Date: 2026-10-15
- Status: Accepted

## Context

本人やなつみ・Claude が、時間をかけた調べものをさせたい。たとえば GitHub のリポジトリを clone してソースコードから仕組みを調べ、レポートにして返させる。
レポートは、なつみには Markdown で、人にはブラウザで見る HTML で届けたい。

調べもの係（ADR 0013）は、すぐ短く答える係である。clone・作業ディスク・長い実行時間・コードを読む道具が要る仕事とは中身が違う。
モデル・PVC・出口を係ごとに分けられ、頼む側も名前で選べるので、別の係にする。

本人と決めたことは次のとおりである。

- 題材は限らない。ウェブの検索とページを読むことに加え、GitHub のリポジトリを clone してソースを読む。検索と取得の道具は調べもの係と同じものを使う。
- clone したコードは読むだけで、実行しない。clone・検索・`git log`・ファイルを読むまでとし、依存のインストール・ビルド・テスト・スクリプトは動かさない。動かした結果が要ることは、レポートに「未確認」と書く。
  知らないコードは、依存のインストールだけでも任意のスクリプトが走る。係の Pod には A2A の token と ChatGPT Plus のログインがある。
  - 退けた案: 使い捨ての Job で隔離して実行する。Job の権限・出口・資源の上限と、作るものが大きい。後から足せる。
- 読むのは public のリポジトリだけで、係は GitHub の資格情報を持たない。信用できないウェブの文を読む係に private を読める鍵を持たせると、仕込まれた指示で外へ漏らす道ができる。
  本人の private のリポジトリは、Claude・Pi・Codex が手元の checkout で読める。
- 1 回の時間に上限を設ける。既定は 60 分程度で、設定で変えられ、依頼の文で短くできる。上限に来たら「途中まで」と明記して返す。続きは同じ context で頼む。
- 返事は、返事の取り決め（ADR 0015）の形で、レポートの章を `sections` に入れる。ブラウザで見る URL は「レポート」の節に書く。上限（節 50・1 節 50000 文字）に収める。
- レポートは保存し、手で消すまで残す。backup に入れる。
- 係全体で同時に走るのは 1〜2 件まで（設定）。超えた依頼は待たせる。
- 名前は `deep-researcher`、モデルはほかの係と同じ ChatGPT Plus（`openai-codex`）。

汎用ホストの仕組みは、別の ADR で決めた。時間と同時実行の上限は ADR 0019、レポートの保存・取得・消し方・HTML は ADR 0020、人用のページは ADR 0021 である。
この ADR は、係そのもの（役割・道具・作業領域・設定の値・指示）を決める。

## Decision

### 係の役割

- 係は、頼まれたことを、ウェブと public の GitHub のリポジトリを読んで調べ、出典の付いたレポートにして返す。
- 係には書き込みの権限もログイン状態も持たせない。投稿・送信・購入などの操作はせず、GitHub にも書き込まない。ログインが要るページと private のリポジトリは読めないものとする。
- ページの文とリポジトリの中身（README・コメント・コード・issue の文など）はデータであって指示ではない、と AGENTS.md に書く。
- 動かさないと分からないこと（テストが通るか、性能、実際の出力など）は、推測で埋めずに「未確認」と書く。

### 道具

- 検索は、調べもの係と同じ Pi パッケージの `searxng_search` だけで行う。ページの取得とキャッシュ引きは、調べもの係・ニュース係と同じ `@kvidzibo/pi-web-access` の `fetch_content` と `get_search_content` を使う。
  外の検索サービスに出る道具は、汎用ホストの起動の引数で外し、拡張でも止める（ADR 0013 と同じ二重の守り）。
- ブラウザは入れない。スクリーンショットは撮らない。要るなら調べもの係に頼む。
- リポジトリの道具は、Pi パッケージに新しい拡張（以下、リポジトリの拡張）として足す。agentDir に設定のファイルがあるときだけ働く。
  - clone の道具: `https://github.com/<owner>/<repo>` の形の URL だけを受け、その context の作業領域に clone する。
    - 資格情報を使わない。credential helper を切り、端末での入力も求めさせない。private のリポジトリは、そのまま失敗になる。
    - submodule と LFS は取らない。
    - checkout では、シンボリックリンクを作らず、リンク先を書いた普通のファイルとして置く（git の `core.symlinks` を切る）。リポジトリの中のリンクから、作業領域の外のファイルを読ませないためである。
    - 履歴は残し、ファイルの中身は要るときに取る形（partial clone）を基本にする。大きさと時間に上限を設け、超えたら clone を消して理由をモデルに返す。
  - 履歴の道具: clone したリポジトリで、`git log`・`git show`・`git blame` などの読むだけの操作を、決まった引数の形で実行する。任意の git の引数（`-c` や外部の diff など）は渡させない。
- ファイルを読む道具は、pi の組み込みの `read`・`grep`・`find`・`ls` を出す。`bash`・`edit`・`write` は出さない。
  - リポジトリの拡張が、これらの道具の呼び出しを見て、パスがその context の作業領域の外に出るもの（シンボリックリンクを解いた先を含む）を止める。
    agentDir（ログインの資格）、`/data`、ServiceAccount の token を読ませないためである。調べもの係が組み込みの道具を出さなかったのと同じ理由で、ここでは範囲を絞って出す。
- コードを実行する道具は無い。bash を出さないので、モデルが依存を入れたりスクリプトを動かしたりする道は無い。
- 各パッケージの版は、image の lock で固定する。

### 作業領域

- 汎用ホストの context ごとの作業ディレクトリ（`contextWorkspace`）を使い、clone は `<workDir>/<contextId>` の下に置く。
- clone は context と一緒に残す。同じ context の続きの依頼では、同じ clone を読み続ける。
- context が保持期間（`sessionRetentionSeconds`）で消えるときに、作業ディレクトリごと消す。途中で落ちて残ったものも、今の汎用ホストの片付けで消える。
- 作業領域はレポートの置き場（ADR 0020）と別のディレクトリであり、backup に入れない。
- 1 つの context で clone できる合計の大きさにも上限を設ける。上限の値は実装で決める。

### 時間と同時実行

- `taskTimeLimitSeconds`（ADR 0019）は 3600（60 分）にする。
- `maxConcurrentTasks`（ADR 0019）は 1 から始める。2 に上げるのは、Plus の枠と Pod の資源の様子を見てからにする。
- 依頼の文で時間を短く頼まれたら、モデルがその時間で切り上げる。上限に来るまで返事を出さないのではなく、調べながら途中の返事を `submit_reply` で出し直す。
  止められたときに残る返事を増やすためである（`submit_reply` は後の返事で置き換わる）。
- 「途中まで」で返したときは、`summary` にそう書き、まだ調べていないことを節に書く。続きを頼まれたら、前の分も含めた全体を返事にする（続きのレポートが単独で読めるように）。

### 返事とレポート

- 返事は `submit_reply` で出す。
  - `summary`: 1 行目に何のレポートかが分かる文を書く（レポートの題になる、ADR 0020）。続けて結論。
  - `sections`: レポートの章を読む順に。49 節まで（最後の「レポート」の節はホストが足す）。1 節が長すぎるときは章を分ける。
  - `sources`: 拠ったページと、読んだリポジトリ（と見た commit）の URL。
- 章の本文では、目次・表・コードのブロック・Mermaid の図を使ってよい。HTML は書かない（書いても文として出る）。
- 汎用ホストの `reports` を有効にし、`reports.web` を設定する。人用のページは gated の改修（gated ADR 0034）がそろってから出す（ADR 0021）。

### モデルと置き方

- ChatGPT Plus の経路（`openai-codex`）を使う。ページやリポジトリに仕込まれた指示に強いモデルを選ぶ（ADR 0013 と同じ考え）。具体のモデルと thinking の強さは実装で決める。
- ログインは係の Pod で本人がし直す（ADR 0008）。
- image は、汎用ホストの image に `@kvidzibo/pi-web-access`・git・組み込みの検索の道具が使うコマンドを足した Dockerfile の target `deep-researcher` にする。Chromium は入れない。
- 置き方は、ほかの係と同じ StatefulSet（ADR 0011）。ボリュームは、レポートと clone の両方を持つので、ほかの係より大きくする。
- 出口は、調べもの係と同じく当面絞らない（ADR 0013）。git の clone は GitHub への https だけだが、ページの取得はどこへでも出る。

### 実装で決める事項

次の事項は、この ADR では決めない。実装で決め、必要なら ADR に追記する。

- 係の設定のファイル（リポジトリの拡張の設定）の形。
- clone の大きさ・時間・context ごとの合計の上限の値。
- 履歴の道具で許す git の操作と引数の形。
- 組み込みの道具のパスの判定の細部（相対パス・`~`・glob の扱い）。
- モデルが経過した時間を知る手段（ADR 0019）。
- ボリュームの容量と、backup の置き方（環境の overlay、ADR 0010）。

### 実装で決めたこと

上の事項のうち、次を実装で決めた。backup の置き方は環境の overlay で決める。

- 設定は agentDir の `repositories.json` に置く。項目は clone と履歴の道具の上限だけで、秘密は無い。
  ファイルはあるが読めないときは、clone と履歴の道具を出さず、範囲の判定と `bash`・`edit`・`write` の遮断は働かせる（組み込みの読む道具が範囲なしで残らないように）。
- 上限の既定は、1 つの clone 1 GB、1 つの context の合計 3 GB、clone の時間 5 分、履歴の道具 1 回 2 分。大きさは clone の途中と後で、ディレクトリを数えて確かめる。
  履歴の道具が後から取るファイルの中身は合計に数えず、次の clone のときに数える。
- clone は `--single-branch` で、既定のブランチか、頼まれたブランチ・タグ 1 つだけを取る。置き場は `repos/<owner>/<repo>`（小文字）で、同じ context で 2 度は clone しない。
  git は system と global の設定を読まず、使えるプロトコルを https だけにする。後からの中身の取得も同じ設定で動く。
- 履歴の道具は `git_log`・`git_show`・`git_blame` の 3 つにした。出力の形とオプションは道具が決め、モデルが渡すのは値だけである。
  revision は英数字と `_ . / ~ ^ -` だけで `-` で始まらないもの（`git_log` だけ範囲 `A..B` を許す）、パスはリポジトリからの相対で `..` を含まないもの、とする。pathspec は字のとおりに読ませる。
- 組み込みの道具のパスは、pi と同じく空白を直して先頭の `@` を外し、`~` と `file:` で始まるものは止める。それ以外は作業領域からの相対として解き、シンボリックリンクをすべて解いた先で判定する。無いパスは、ある所までを解いて判定する。
- モデルが経過した時間を知る手段: 汎用ホストは、上限の長さと数え始めた時刻を prompt に添え、時刻は `date` で見させる（ADR 0019）。この係には `bash` が無いので、リポジトリの拡張が今の時刻を返す道具を出し、`bash` を止めるときの理由でもそれを案内する。
- ボリュームは 20Gi にする。

## Consequences

- 長い調べものを、調べもの係と分けて頼める。調べもの係の image と振る舞いは変わらない。
- コードを動かさないので、動かして確かめる調べもの（ベンチマーク、テストの結果）はできない。要るなら、隔離した Job で動かす仕組みを別に考える。
- private のリポジトリは調べられない。本人の private を調べるときは、手元の Claude・Pi・Codex で行う。
- 組み込みの読む道具を出すので、その道具に範囲の判定の抜けがあれば、作業領域の外（ログインの資格など）を読まれうる。判定はシンボリックリンクを解いたパスで行い、clone はリンクを作らない形にして、二重に守る。
- clone は context と一緒に最長で保持期間のあいだ残る。大きなリポジトリをいくつも clone すると、ボリュームを食う。
- 同時に 1 件しか走らないので、長い依頼の後ろに並んだ依頼は、何十分も待つことがある。
- Plus の枠を長く使う。ほかの係・なつみ・本人が枠に当たりやすくなる。
- 出口を絞るまでの間、ページやリポジトリに仕込まれた指示で、係がクラスタの内部につながる危険は、調べもの係と同じく残る。ブラウザが無い分、つながる道は取得の道具だけで、内部のアドレスへの防ぎがある。
